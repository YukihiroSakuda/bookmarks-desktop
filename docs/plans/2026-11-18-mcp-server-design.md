# 設計: ブックマークを AI アシスタントの「地図」にする（MCP サーバー）

- **日付**: 2026-11-18
- **ステータス**: 実装済み

## 背景 / 目的

ブックマークには、仕事のどこに何があるかがすでに詰まっている。どのページ・ファイル・フォルダを使うか、
それをどう分類しているか（タグ）、何と呼んでいるか（メモ）、いま何を使っているか（開いた回数と最終アクセス日時）。

AI アシスタント（Claude Desktop、Claude Code など）は、これを知らないので毎回ユーザーに聞くか、
ディスクを手当たり次第に探すことになる。MCP で読めるようにすれば、AI が自分で地図を引いてから動ける。

## 重要な決定

| 論点 | 決定 | 理由 |
|---|---|---|
| トランスポート | **stdio**（`app.exe --mcp`） | Claude Desktop・Claude Code・Cursor・VS Code のどれもが標準で対応する唯一の方式。既存の HTTP サーバー（37373）に載せると、Claude Desktop では `mcp-remote` などの中継が要り、トークンの受け渡しも要る |
| プロセス | **アシスタントが起動する別プロセス**。`main.rs` で Tauri 起動前に分岐 | single-instance プラグインに既存アプリへ転送されない。ウィンドウもトレイも出ない。アプリが起動していなくても動く |
| 書き込み | **しない**（`SQLITE_OPEN_READ_ONLY`） | AI が何を頼んでも変更・削除が起き得ない、と一言で説明できる。書き込むと別プロセスから UI へ通知できず、ショートカットフォルダの同期も漏れる |
| 接続 | **ツール呼び出しごとに開いて閉じる** | 呼び出しの合間にロックを持たない。アシスタントの起動後に DB が作られても（アプリの初回起動）見つかる |
| 同時アクセス | アプリ側の接続にも `busy_timeout` 5 秒 | MCP の読み取り中にアプリが書いても、`SQLITE_BUSY` で失敗せず数ミリ秒待つ |
| SDK | **使わない**（JSON-RPC を手書き） | 必要なメソッドは `initialize` / `tools/list` / `tools/call` / `ping` だけ。非同期ランタイムと変化の速いクレートをデスクトップアプリに入れる理由がない |
| DB の場所 | `dirs::data_dir()` + 識別子。`--db <path>` で上書き可 | Tauri の `app_data_dir()` と同じ解決方法。識別子は `tauri.conf.json` と二重定義になるため、テストで一致を確認する |

## ツール

| ツール | 内容 |
|---|---|
| `get_overview` | 最初に呼ぶ。件数、全タグと件数（ユーザー自身の仕事の分類＝地図の凡例）、ピン留め、最近よく使うもの |
| `search_bookmarks` | タイトル・メモ・タグ・URL/パスを語で検索（全語 AND）。タグ・種別で絞り込み可。クエリなしなら最近よく使う順 |
| `get_bookmark` | 1件の全情報。パスなら存在確認、フォルダなら直下の一覧 |
| `search_files` | ブックマークしたフォルダの中をファイル名で検索。アプリ内のフォルダ内検索（`folder_search.rs`）と同じ歩き方・同じ上限 |

一覧には favicon（base64）や並び順の内部列を含めない。どのブックマークのことかを決めるのに役立つ情報だけを返す。

### メモはタイトルと同じ重み

検索の重みは「タイトル = メモ (3) > タグ (2) > URL/パス (1)」。全語の合計点が同じなら、最近よく使う順に並べる。

メモは実際には**タイトルの別名**として使われていることが多い（`SAP Concur - Home` に「経費精算」）。
これはノイズではなく、ユーザーの呼び方と実際のタイトルをつなぐ対応表で、AI がユーザーの言葉で検索するときに最も効く。
そのためメモでの一致はタイトルでの一致と同じ強さとして扱い、AI への説明文（`instructions`）でもそう伝える。

### 「最近よく使う」はアプリと同じ式

`recencyScore`（`src/lib/bookmarkScore.ts`）を Rust に移植した。半減期 30 日。
アプリの「Most Used」と AI の「in use lately」が別のものを指さないよう、**変更するときは両方を直す**。

## 設定画面

**Settings → AI assistants** に、その環境での起動コマンドと、Claude Desktop 用の設定 JSON・Claude Code 用のコマンドのコピーボタンを置く。
ストア版の `app.exe` は更新のたびにフォルダ名が変わり、直接起動するとパッケージ ID も失うため、
起動コマンドには実行エイリアス `bookmarks-tags.exe` を使う（`mcp_launch_command`）。

## プライバシー

アプリ自体は通信しない。AI が読んだ内容は、そのアシスタントが使う AI サービスに送られる。
ユーザーが自分でアシスタントに登録するまでは何も起きない。`docs/privacy-policy.md` に節を追加した。

## 今回やらないこと

- **書き込み**（AI がブックマークやメモを追加する）: 「読み取り専用」という保証と引き換えになる。要るなら、メモの別名欄を汚さない形（AI 用の追記欄や提案キューなど）を別に設計する
- **アクセス履歴**: いまは回数と最終日時しかない。「一緒に開かれるもの」から作業のまとまりを推定するには、開いた記録を残す表が要る
- **ファイルの中身**: `search_files` はファイル名だけ。中身は、ファイルを読めるアシスタント（Claude Code など）が場所を知ったうえで自分で読む
